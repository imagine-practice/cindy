## 1. M3：项目级访问与群聊收敛

目标：成员身份决定"能不能看、能不能派"，群聊从协作前提降为沟通频道。

### M3-A 访问判定（主进程）

- 读路径：项目列表、项目详情、工作项、材料列表/预览，统一经一个 `canViewProject(subject, project)` 判定；非成员返回空结果 + 明确原因，**不返回 403 之外的正文片段**。
- 写路径：建任务、绑项目、设处理人、增删成员、转交负责人，统一经 `canManageProject`（负责人或成员，按最小权限约定：成员可建任务与设处理人，只有负责人能改成员与转交）。
- 单账号现实：人只有一个账号，本节主要保护"伙伴侧"——非成员伙伴不能通过工具读写项目数据。
- 可见性必须与 M2 材料的 `storage_kind='file'` 对齐：非成员拿不到任何 `storageRef` 或预览地址。

### M3-B 群聊收敛（串行，排在 A 之后）

- 群聊保留，但不再是项目协作前提：群里发起的需求可以关联到项目，关联是显式动作，不自动建项目。
- 群里被 @ 的伙伴若不是项目成员，只能回复"未加入该项目"，不得读取项目材料。
- 不在本轮删除群功能，只改语义与入口文案。

### 验收

| ID | 操作 | 预期 |
| --- | --- | --- |
| P1 | 非成员伙伴请求项目详情/材料列表/预览 | 空结果 + 原因；无正文、无地址、无文件名 |
| P2 | 成员建任务、设处理人 | 成功；非成员被拒，错误码明确 |
| P3 | 成员尝试改成员/转交负责人 | 被拒；负责人才可 |
| P4 | 撤出成员后其工具调用 | 立即失效，历史记录仍可追溯但不含正文 |
| P5 | 群内 @ 非成员伙伴要求读项目材料 | 明确未加入，不泄露 |

## 2. M4：进度视图与自动化

目标：项目从"能建能派"变成"能看进度"。

- 工作项状态机：`todo / doing / blocked / review / done`，与任务状态映射规则写死在一个纯函数里，不散落界面。
- 项目概览：按状态计数、阻塞项列表、最近活动；不做燃尽图与工时。
- 阻塞登记：工作项可记录阻塞原因与解除条件，解除时留痕。
- 自动化联动：现有定时任务可绑定项目，产出默认归到该项目；不做新的调度器。
- 验收：状态流转可回退且留痕；计数与列表同源；空态、加载、失败齐备；320/390 与浅深主题可用。

## 3. 明确不做

- 多账号共享项目、跨设备同步、项目级 RBAC 细粒度角色。
- 甘特图、工时、预算、燃尽。
- 材料 OCR / PDF 正文解析。
- 删除群聊能力。
